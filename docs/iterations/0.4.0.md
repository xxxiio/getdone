# Iteration 0.4.0

## Why this work was next

Version 0.3.0 safely classified modified project-owned files but left reviewers with only whole-file diffs. The recorded next deterministic step was to add structural Markdown evidence without weakening the no-overwrite boundary.

No higher-priority unfinished template-lifecycle work needed to precede this read-only capability.

## Delivered

- Cohesive, separate ATX Markdown parsing and comparison modules with fenced-code awareness.
- Deterministic matching for repeated headings using content similarity and stable order.
- Added, removed, heading-changed, content-changed, and reordered classifications.
- Conservative probable-rename detection with confidence values.
- Direct section-content diffs for matched changed sections.
- `merge_suggestion` objects in JSON update and migration plans.
- `--sections` human-readable output for both lifecycle commands.
- JSON Schema for the merge-suggestion contract.
- Explicit documentation that the result is two-way evidence, not an automatic three-way merge.
- Tests proving that modified files remain read-only under replacement authorisation.
- Explicit `--skills-root` and `--repository-root` command options so an installed tooling wheel can operate against a separate shared-repository checkout.

## Validation

- Repository validation passed.
- Front-matter and manifest validation passed.
- JSON Schema validation passed for representative merge suggestions.
- 45 unit and integration tests passed.
- Direct-script and installed-wheel console smoke tests passed.
- Python compilation, Git whitespace, line-length, and function-length checks passed.
