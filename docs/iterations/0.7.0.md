# Iteration 0.7.0: Skill Authoring and Registry Lifecycle

## Why this was the highest-priority next step

The 0.6 catalogue made reusable guidance discoverable but did not define how stable identities evolve, how entries are deprecated safely, how human indexes remain synchronised, or how organisations extend the catalogue without forking it. Those gaps could cause incompatible identifiers and divergent agent behaviour.

No higher-priority unfinished category preceded this work: core workflows, project-state bootstrapping, template lifecycle, maintainability, distribution, and basic reuse discovery were already complete.

## Delivered

- Skill-authoring lifecycle workflow and acceptance gate.
- Proposal, registry-review, and deprecation-plan templates.
- Registry schema v2 lifecycle metadata.
- Exact canonical ID and alias resolution.
- Safe deprecation and retirement validation.
- Generated human-readable registry indexes.
- Registry compatibility and schema-evolution policy.
- Organisation catalogue overlay schema, validation, search integration, decision record, and worked example.
- Cross-agent adapter guidance for aliases and explicitly named overlays.

## Validation

- Repository structure, links, workflow metadata, registries, generated indexes, adapters, and overlay example.
- Unit and integration tests for alias resolution, lifecycle rules, index drift, overlay namespaces, overlay search, and JSON Schema conformance.
- Direct-script and installed-console command smoke tests.
- Python compilation, Git whitespace checks, package build, and release artefact checks.

## Internal-testing readiness

The repository remains credibly ready for internal testing: it has an installable development build, executable bootstrap and consuming-project smoke workflows, tested registry and overlay contracts, and no known blocking data-loss issue. Registry and migration writes remain explicit and non-destructive.

## Remaining limitation

No authorised signing key or Git remote is configured. The local release tag is annotated but cannot be represented as a cryptographically verified published release.

## Next deterministic step

Implement project-local skills composition locking so a consuming project can pin the core release, bootstrap profile, adapter contract, and organisation overlays, then validate that every agent resolves the same guidance set.
