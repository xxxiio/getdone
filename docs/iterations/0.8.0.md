# Iteration 0.8.0: Pinned Composition and Reproducibility

## Why this was the next step

Distribution, adapter, reuse, and registry lifecycle work was already complete. The highest-priority unresolved risk was that two agents could use different shared checkouts, profiles, or overlays while appearing to follow the same project instructions.

## Delivered

- Project-local `.agent/skills.lock.json` generated during bootstrap.
- Independent pins for core guidance, profile templates, adapter contracts, and organisation overlays.
- Location-independent composition digests.
- Same-version drift detection and semantic update classification.
- Strict project validation and read-only lock planning.
- Overlay version provenance in catalogue search and project validation.
- Adapter contract 1.3.0 and profile bundle 1.3.0.
- Catalogue search JSON schema version 3.
- Migration and distribution documentation.

## Token and context efficiency

The lock contains metadata and hashes rather than copied guidance. A standard project with the example overlay produced a 1,106-byte lock. The canonical core guidance measured about 171,169 characters, so the lock is roughly 0.65% of that character volume. Using the coarse four-characters-per-token approximation, this is about 276 tokens versus 42,792 tokens.

This is not presented as a prompt benchmark. It demonstrates that composition can be verified cheaply before loading only the selected workflow, relevant practices, and acceptance gates. The next milestone will benchmark task accuracy before adding any context-selection getdone.

## Safety properties

- Lock writes require `--write`.
- Existing overlay references are preserved unless replacements are explicitly supplied.
- Overlay file-system locations do not affect composition identity.
- Same-version content changes are classified as drift.
- Modified project-owned Markdown is outside the lock write path.
- Project validation requires the resolved composition to be current.

## Validation

- 95 tests passed.
- Repository, front-matter, registry-index, release-metadata, compilation, and whitespace checks passed.
- Changed Python code has no lines over 100 columns and no functions over the 50-line review trigger.
- Source and installed-wheel adoption paths passed with `org.example@1.0.0` provenance.
