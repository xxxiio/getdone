# Iteration 0.3.0

## Why this work was next

Version 0.2.0 could identify safe template updates but could not apply them, and profiles could not be layered without copying entire template trees. Completing the template lifecycle was therefore the highest-priority deterministic step before expanding distribution or reuse intelligence.

The maintainability guidance was added after the migration core because it fits the existing refactoring and acceptance layers without destabilising the migration design.

## Delivered

- Parent-first profile inheritance with deterministic child overlays.
- Cycle, unknown-parent, source-directory, and manifest-schema validation.
- Profile version and lineage provenance in generated project state.
- Unified migration diffs.
- Dry-run migration application by default.
- Independent authorisation for missing-file additions and verified-unmodified replacements.
- Protection for modified, untracked, mismatched, invalid, and ahead files.
- Guard against claiming a target profile while required inherited additions remain pending.
- Organisation-profile layering example and migration documentation.
- Complexity and maintainability guidance for functions, types, files, modules, dependencies, and design-pattern use.
- Core maintainability acceptance gate and language-specific interpretations.

## Validation
