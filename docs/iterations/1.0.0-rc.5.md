# Iteration 1.0.0-rc.5: Generated Documentation Site

## Why this was the highest-priority next step

The package had reached a level of structural depth where public adoption was limited more by discoverability than by missing engineering controls. A generated site provides a high-value navigation layer without increasing normal agent context or creating a second source of truth.

## Scope

- Add Zensical as an optional, pinned documentation dependency.
- Add a dedicated site source tree and explicit navigation.
- Generate workflow, reusable-skill, language, policy, template, adapter, schema, and CLI catalogues from authoritative repository sources.
- Add generation drift checks, tests, and CI strict-build coverage.
- Add public usage and maintainer guidance.

## Non-goals

- No new development workflow or language standard.
- No change to consuming-project record schemas or bootstrap profiles.
- No custom theme, analytics, hosted deployment target, or repository-specific branding.
- No generated content is loaded into normal task context.

## Acceptance evidence

- Generated documentation unit tests pass.
- Full repository tests pass.
- Repository validation rejects generated-page drift.
- `zensical.toml` uses a dedicated `site_docs/` directory and explicit catalogue navigation.
- CI installs the optional docs dependency and runs `zensical build --strict`.

## Internal-testing readiness

The repository remains credible for internal testing: tooling is runnable, project bootstrap and rollout smoke workflows pass, and no known data-loss blocker exists. Public release still requires hosted CI and an independent documentation-led adoption run on the exact candidate.
