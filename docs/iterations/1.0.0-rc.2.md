# Iteration 1.0.0-rc.2: Content Architecture Correction

## Objective

Resolve rollout feedback that canonical content was too granular, mixed with repository
development files, and too vague for deterministic execution.

## Changes

- Moved all canonical content beneath `skill/`.
- Consolidated core and language practices and acceptance gates.
- Rewrote procedures, standards, gates, and policies as operational contracts.
- Moved registry-backed worked examples into the product boundary.
- Added a standalone skill-pack builder and end-to-end adoption test.
- Added product-boundary, operational-content, link-boundary, and context-size checks.
- Added an RC.1-to-RC.2 migration guide.

## Measured outcome

- Normal context: 17 documents → at most 6.
- Average selected tokens: ~4,856 → ~2,698.
- Reduction from RC.1 selected context: 44.43%.
- Routing and required-document recall: 100%.
- Missed gates: 0.
- Rollout cases: 3 passed.

## Scope control

No workflow family, language, adapter, registry concept, or automation was added.

## Next step

Use RC.2 in internal repositories, accept rollout-blocking fixes only, then promote to
`v1.0.0`.
