# Iteration 0.2.0 Report

## Why this was the highest-priority next step

The core workflow and bootstrap boundary were already usable. The largest remaining correctness risk was template evolution: without provenance and migration planning, future shared-template changes could overwrite project-owned state or become impossible to assess safely. Workflow depth was the other highest-priority unfinished roadmap category and could be completed alongside the acceptance structure it required.

No higher-priority unfinished core-operating-system work preceded this iteration.

## Completed

- Added specialised architecture, database, performance, UI/mobile, multi-agent, and handoff workflows.
- Added corresponding change-type acceptance gates.
- Expanded language practices and acceptance criteria for all five initial language families.
- Added template identity, semantic version, ownership, and generated digest provenance.
- Added a read-only template update checker with human-readable and JSON output.
- Added modification, missing-file, version, mismatch, and safety classification.
- Added workflow and bootstrap-template schema validation.
- Added installable CLI entry points and CI installation.
- Added template lifecycle, migration, and upgrade policy documentation.

## Validation evidence

- Repository validation
- Front-matter schema validation
- Unit and integration tests
- Direct-script CLI smoke checks
- Python compilation
- Editable package installation and console-command smoke checks
- Git whitespace checks

## Known limitations

- The checker plans updates but does not apply them.
- Modified files do not yet receive section-aware merge suggestions.
- Organisation-specific inherited profiles are not yet implemented.
- Ruff and Pyright are optional project checks and may not be available in every execution environment.

## Next deterministic step

Implement profile inheritance and an explicit migration-application command that defaults to dry-run, emits diffs, applies only safe additions or verified-unmodified replacements, and requires separate authorisation for each write category.

This remains within template lifecycle, the highest-priority unfinished roadmap milestone.
