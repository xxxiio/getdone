# Iteration 0.5.0

## Why this work was next

Version 0.4.0 completed safe template review but left adoption and agent-specific integration under-documented. The recorded next deterministic step was to make distribution models explicit, test thin adapters, and prove a consuming repository could bootstrap and validate without copying shared workflows.

No higher-priority unfinished template-lifecycle work needed to precede this distribution layer.

## Delivered

- Supported distribution models for adjacent/global checkouts, submodules, vendored snapshots, and installed tooling paired with a shared checkout.
- Schema-backed adapter manifest and contract validation.
- Thin project-file adapters for Claude Code, Cursor, and GitHub Copilot.
- Bootstrap-managed Codex integration and reference-only ChatGPT guidance.
- Non-destructive adapter installer with explicit overwrite behaviour.
- Consuming-project validator that distinguishes invalid state from valid project-owned modifications and available updates.
- Executable minimal Python consuming-project example exercised end to end.
- Release metadata and tag verification getdone.
- Maintainer-signed-tag policy with honest unsigned-development-tag handling.

## Safety properties

- Adapters cannot create a second project-state directory.
- Existing project adapter files are not overwritten by default.
- A project must be bootstrapped before adapters can be installed.
- Modified managed project state remains valid and project-owned.
- Missing, untracked, mismatched, unmanaged, or invalid-version managed state fails project validation.
- The tooling wheel does not pretend to contain canonical shared Markdown.

## Validation

- Repository validation passed.
- Front-matter, profile-manifest, and adapter-manifest validation passed.
- Release metadata verification passed.
- 59 unit and integration tests passed.
- The executable consuming-project example passed its own test suite.
- Direct-script commands and installed-wheel console commands passed end-to-end smoke tests.
- A fresh standard project reported 22 of 22 managed files current.
- Python compilation, Git whitespace, changed-code line-length, and function-length checks passed.
- Ruff and Pyright were unavailable in the execution environment.
- Environment-wide `pip check` reported a pre-existing MoviePy/Pillow mismatch unrelated to this repository.

## External limitation

No authorised maintainer signing key or Git remote is configured in this environment. The local release tag can be annotated and verified structurally, but it cannot truthfully be reported as maintainer-signed or remotely published.
