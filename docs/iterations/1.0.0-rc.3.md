# Iteration 1.0.0-rc.3: Controlled Project Records

## Objective

Resolve rollout feedback that bootstrap Markdown outlines gave agents too much freedom to
invent record structure, status meaning, acceptance wording, and update behaviour.

## Changes

- Added one machine-readable contract registry covering all project-owned record templates.
- Added one human semantic contract rather than a separate instruction file per template.
- Added controlled statuses, stable IDs, exact section ordering, checklist formats, and
  evidence rules.
- Added roadmap milestone validation and roadmap-to-next-step cross-reference checks.
- Integrated record validation into `getdone-validate-project` and repository health.
- Added `getdone-validate-records` for focused read-only validation.
- Consolidated duplicate minimal/standard project-context and next-step template sources.
- Added a non-destructive RC.2-to-RC.3 migration guide.

## Scope control

No workflow family, language standard, adapter, registry concept, or automatic planning
capability was added. The validator checks structure and consistency; it does not claim to
verify whether project facts are truthful.

## Token and maintainability impact

- Ordinary coding context remains the same five or six selected documents.
- The project-record contract is loaded only when creating, materially changing, or
  reviewing `.agent/` records.
- Detailed rules are centralised in one contract document and one JSON registry rather
  than repeated in every generated record.

## Next step

Use RC.3 in internal repositories, accept rollout-blocking corrections only, and then
promote the contracts to `v1.0.0`.
