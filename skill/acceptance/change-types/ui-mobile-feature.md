# UI and Mobile Acceptance

## Objective
Deliver a complete user interaction across UI, state, domain, and platform boundaries.

## Pass conditions
Primary, loading, empty, error, accessibility, responsive, localisation, and relevant platform paths have evidence.

## Required evidence
Record the task-specific proof above together with the core gate statuses and commands.

## Waiver conditions
Use the core waiver format; name the unavailable primary evidence, alternative evidence, and residual risk.

## Failure conditions
Visual scaffolding without state/error behaviour or manual-only validation of critical paths.
