# Skill and Registry Acceptance

## Objective
Change reusable guidance only when it reduces repeated reasoning or prevents a material error class.

## Pass conditions
Proposal names trigger, audience, overlap, token impact, examples, tests, schema/index changes, compatibility, and lifecycle metadata.

## Required evidence
Record the task-specific proof above together with the core gate statuses and commands.

## Waiver conditions
Use the core waiver format; name the unavailable primary evidence, alternative evidence, and residual risk.

## Failure conditions
Duplicated advice, vague rules, unmeasured mandatory context, or unstable IDs.
