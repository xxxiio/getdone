# Refactoring Acceptance

## Objective
Improve structure while preserving authorised behaviour and public contracts.

## Pass conditions
A passing baseline exists; characterisation coverage protects weak areas; the claimed structural improvement is shown by dependency, complexity, duplication, or maintainability evidence.

## Required evidence
Record the task-specific proof above together with the core gate statuses and commands.

## Waiver conditions
Use the core waiver format; name the unavailable primary evidence, alternative evidence, and residual risk.

## Failure conditions
Bundled behavioural changes, unmeasured broad rewrites, or reduced test coverage.
