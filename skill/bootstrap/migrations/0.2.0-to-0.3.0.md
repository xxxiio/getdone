# Migration: 0.2.0 to 0.3.0

## Scope

This migration introduces profile inheritance, profile-lineage provenance, and explicit safe migration application.

## Profile changes

- `standard` now extends `minimal`.
- `minimal` and `standard` profile bundle versions advance to `1.2.0`.
- Shared reference templates record profile version and lineage.
- Richer `standard` overrides use template version `2.0.0` so migrations from `minimal` or earlier standard templates are classifiable.

## Recommended procedure

```bash
getdone-check-updates --project-root /path/to/project --diff
getdone-migrate --project-root /path/to/project
getdone-migrate --project-root /path/to/project --apply-additions
getdone-migrate --project-root /path/to/project --apply-replacements
getdone-check-updates --project-root /path/to/project
```

Review the dry-run before either write command. Apply additions before replacements when changing profiles. The migration tool defers profile-reference replacement while required additions remain pending.

## Safe automated actions

- Create missing resolved-profile files after addition authorisation.
- Replace a newer managed template only when its installed copy still matches its generated digest and replacement is authorised.

## Manual actions

Modified, untracked, mismatched, invalid-version, and ahead files require human or agent-guided review. Preserve project decisions, IDs, status, history, and local conventions.

## Rollback

Restore changed project files from version control. The migration command does not delete files and does not modify locally changed project-owned files.

## Validation

- Re-run the update checker and confirm all expected managed files are `current`.
- Run the consuming project's normal health checks.
- Confirm `.agent/skills-reference.md` records the intended profile and lineage.
